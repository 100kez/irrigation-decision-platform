## 二、Bug 修复

### ① 生成灌溉决策报错(点击按钮即报错)

**现象**:点「生成灌溉决策」就报错。

**根因**:服务端实际成功(201,记录已入库),崩溃在结果渲染。`DecisionResultActions.tsx` 中 `timeWindow` 无条件访问 `firstEvent.date`,当灌溉方案为空数组时(土壤湿润、7 天内无胁迫,方案为空——当时 3 条决策全是这种情况)`firstEvent` 为 `undefined`,TypeError 触发 ErrorBoundary 错误页。

**修复**:`client/src/pages/Decision/components/DecisionResultActions.tsx` — 空方案时时间窗口返回 `''`,正常渲染「暂不灌溉」分支。

### ② 首页待处理建议为空但计数显示 2 条

**现象**:待处理建议区块空白(显示"暂无待处理"),但徽章计数是 2。

**根因**:`getDashboard` 中 pendingActions 有 `needsAttention` 过滤(仅干旱/胁迫/有灌溉事件的方案才进列表),而 `pendingCount` 统计全部 pending/adopted,口径不一致。

**修复**:`server/modules/irrigation/irrigation.service.ts` — 移除 `needsAttention` 过滤,所有待处理方案全部展示(空方案的在前端显示「当前方案无需灌溉」),计数与列表一致。

### ③ 首页点击最近决策记录报错

**现象**:点击首页「最近决策记录」中任意一条即报错。

**根因**:与 ① 相同。跳转 `/decision?decisionId=`,`GET /decisions/:id` 返回 200,渲染结果区时 `DecisionResultActions` 因空方案崩溃(用户点的那条 `3e49aab5` 方案为空)。

**修复**:同 ①,一并解决。

### ④ AI 诊断助手无法上传图片

**现象**:上传图片不成功。

**根因**(三重问题):

1. 前端 `handleImageSelect` 对 `file.type` 非 `image/*` 的文件静默丢弃,部分浏览器/文件管理器上报的 `file.type` 为空串 → 选择图片后无任何反应
2. 手机原图 base64 可达数 MB,而 NestJS 默认 JSON body 限制为 **100kb**(Nest 默认值,框架 `configureApp` 未覆盖)→ 即使图片送出去也会 413
3. 聊天失败时前端只显示固定文案「诊断服务暂时不可用」,真实错误信息被吞掉,无法定位

**修复**:

- `client/src/components/AiDiagnosticChat.tsx`
  - 按扩展名兜底判断图片类型(`.jpg/.jpeg/.png/.gif/.webp/.bmp`),非图片 toast 提示
  - 新增 canvas 压缩:最长边 1280px、JPEG 质量 0.85(解码失败如 HEIC 时退回原图)
  - 失败消息改为展示服务端真实错误(`data.error.message`)
- `server/main.ts` — `app.useBodyParser('json', { limit: '20mb' })` 与 nginx `client_max_body_size 20m` 对齐(urlencoded 同步提升)

**模型能力验证**:实测 `deepseek-chat` 现已路由到 `deepseek-flash`,**支持图片输入**(1x1 PNG data URL 测试返回正确描述),模型层无问题。

## 三、顺手修复的隐患

### jsonb 双编码(数据格式不一致)

**现象**:`irrigation_decision` 的 jsonb 列(`execution_records` 等)混存真数组 `[]` 与 JSON 字符串 `"[]"` 两种格式;SQL 层 `jsonb_array_length()` 直接报 `cannot get array length of a scalar`。

**根因**:写入时对 jsonb 列传 `JSON.stringify(...)` 产生的字符串,驱动把字符串按 JSON 字符串存储(双编码)。应用层 `parseJson` 同时兼容两种格式所以功能没炸,但任何直连 SQL 的查询/统计都会踩雷。

**修复**:`irrigation.service.ts` 中 `createDecision`/`addExecution`/`updatePlan` 改为直接传对象/数组。历史 3 行保持原样(应用层兼容),新数据将按真实 JSON 数组入库。

### 错误信封读取错误

框架错误响应格式为 `{error:{code,message,details,timestamp}}`,前端原先读 `response.data.message` 永远取不到值。已统一改为读 `response.data.error.message`:

- `client/src/pages/Decision/DecisionPage.tsx`
- `client/src/pages/Decision/components/PlanActionBar.tsx`(3 处)
- `client/src/components/AiDiagnosticChat.tsx`
